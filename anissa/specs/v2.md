# K-anIssA — Spécification v2

> Ajout du concept d'URL d'accès comme propriété standard de chaque plan : déclaration dans le `k2.apply.yaml`, génération automatique du `links.env` par les recettes, nouveau verbe `url` et commande `anissa urls`.

---

## Changements par rapport à v1

### Résumé

- **Ajout** : Champ `accessUrl` dans les `vars` du `k2.apply.yaml` de chaque plan.
- **Ajout** : Génération automatique du fichier `links.env` par les recettes `docker-compose` et `shell-script` à partir du champ `accessUrl`.
- **Ajout** : Verbe `url.sh` généré automatiquement par les recettes — retourne l'URL d'accès du plan.
- **Ajout** : Commande `anissa urls <stack>` pour afficher le tableau consolidé des URLs d'accès de tous les plans de la stack.
- **Ajout** : Target `make urls` dans le `Makefile` racine.
- **Ajout** : Fonction `layer_get_url()` dans `anissa/lib/layers.sh`.
- **Modification** : Les recettes `docker-compose` et `shell-script` gèrent désormais un paramètre `accessUrl` et génèrent le `links.env` et le verbe `url.sh` correspondants.
- **Modification** : `anissa up` affiche systématiquement le tableau des URLs d'accès en fin d'opération, y compris pour les plans shell-script.
- **Modification** : `anissa status` affiche l'URL d'accès à côté du statut de chaque layer.
- **Suppression** : Les fichiers `links.env` manuels ne sont plus nécessaires — ils sont désormais autogénérés par le rendering k2. Les `links.env` manuels existants restent compatibles (fallback).

### Justification

En v0/v1, les URLs d'accès sont déclarées dans un fichier `links.env` optionnel, maintenu manuellement dans chaque plan. Ce mécanisme souffre de plusieurs limitations :

1. **Incohérence** : seuls 2 plans sur l'ensemble du projet déclarent un `links.env` (open-webui, vscodium), alors que de nombreux plans exposent des services accessibles (wetty, litellm, ollama, etc.).
2. **Duplication** : le port et le label sont déjà définis dans les `vars` du `k2.apply.yaml` — les redéclarer dans un fichier séparé viole le principe DRY.
3. **Pas d'intégration template** : le `links.env` n'est pas généré par k2, il échappe donc au cycle de rendering automatique.
4. **Pas de verbe dédié** : aucun moyen programmatique de récupérer l'URL d'un plan (utile pour les scripts d'intégration, les healthchecks, etc.).

La v2 fait de l'URL d'accès une **propriété de premier ordre** du plan, intégrée au système de recettes et de rendering.

### Impact sur v1

Aucun changement de comportement par défaut pour les plans existants sans `accessUrl`. Les plans qui ne déclarent pas d'`accessUrl` n'ont simplement pas d'URL affichée. Les fichiers `links.env` manuels existants restent lus en fallback si aucun `accessUrl` n'est défini dans le plan. Toutes les fonctionnalités v0 et v1 restent identiques.

## 1. Champ `accessUrl` dans le plan — Spécification

### 1.1 Déclaration

Chaque plan peut déclarer une ou plusieurs URLs d'accès via le champ `accessUrl` dans ses `vars` :

**Format simple (une seule URL)** :

```yaml
k2:
  body:
    vars:
      name: kanissa-wetty
      title: "Wetty SSH Web Client"
      accessUrl: "http://localhost:${WETTY_PORT:-3000}"
      composeFile: |
        ...
```

**Format multiple (plusieurs URLs)** :

```yaml
k2:
  body:
    vars:
      name: kanissa-litellm
      title: "LLM Proxy"
      accessUrl: |
        LLM Proxy API=http://localhost:${LITELLM_PORT:-4000}
        LLM Proxy UI=http://localhost:${LITELLM_PORT:-4000}/ui
      composeFile: |
        ...
```

### 1.2 Syntaxe du champ `accessUrl`

| Format | Syntaxe | Exemple |
|---|---|---|
| URL simple | `<url>` | `http://localhost:3000` |
| URL avec label | `<label>=<url>` | `Wetty Terminal=http://localhost:3000` |
| URLs multiples | Multiligne `<label>=<url>` | Voir format multiple ci-dessus |

**Règles** :

- Si le format est une URL simple (sans label), le label est automatiquement dérivé du champ `title` du plan.
- Les variables d'environnement (`${VAR:-default}`) sont supportées et résolues au moment de l'affichage par le CLI.
- Le champ `accessUrl` est **optionnel**. Les plans sans URL d'accès (ex: `workspace-keypair`, `google-adc`) l'omettent.

### 1.3 Paramètre dans les recettes

Le champ `accessUrl` est ajouté comme paramètre par défaut dans les recettes, avec une valeur vide :

**Recette `docker-compose`** (`recettes/docker-compose/k2.template.yaml`) :

```yaml
k2:
  metadata:
    id: k.anissa.recettes.docker-compose
    kind: "template"
  body:
    name: "docker-compose"
    parameters:
      name: "sample"
      title: "Sample Component"
      description: "Name of the new app"
      accessUrl: ""
      composeFile: |
          services:
            workspace:
              build:
                context: .
              container_name: sample
              restart: unless-stopped
    scripts:
      pre: []
      nuke: []
```

**Recette `shell-script`** (`recettes/shell-script/k2.template.yaml`) :

```yaml
k2:
  metadata:
    id: k.anissa.recettes.shell-script
    kind: "template"
  body:
    name: "shell-script"
    parameters:
      name: "sample"
      title: "Sample Script"
      description: "Execute a shell script on up and/or down"
      accessUrl: ""
      upScript: |
        echo "up: {{ .name }}"
      downScript: |
        echo "down: {{ .name }}"
    scripts:
      pre: []
      nuke: []
```

## 2. Génération automatique du `links.env` — Spécification

### 2.1 Principe

Les recettes génèrent automatiquement un fichier `links.env` dans le dossier du plan lors du rendering k2, à partir du champ `accessUrl` des vars.

### 2.2 Template `links.env`

Un nouveau fichier template `links.env` est ajouté dans chaque recette :

**`recettes/docker-compose/links.env`** (template Go) :

```
{{ if .accessUrl }}{{ .accessUrl }}{{ end }}
```

**`recettes/shell-script/links.env`** (template Go) :

```
{{ if .accessUrl }}{{ .accessUrl }}{{ end }}
```

### 2.3 Résultat du rendering

Pour un plan avec `accessUrl: "http://localhost:${WETTY_PORT:-3000}"` et `title: "Wetty SSH Web Client"`, le rendering produit :

```
layers/10.clients/wetty/
├── k2.apply.yaml
├── compose.yml           # AUTOGENERATED
├── links.env             # AUTOGENERATED — à partir de accessUrl
├── Makefile              # AUTOGENERATED
└── verbs/
    ├── up.sh             # AUTOGENERATED
    ├── down.sh           # AUTOGENERATED
    ├── logs.sh           # AUTOGENERATED
    ├── shell.sh          # AUTOGENERATED
    └── url.sh            # AUTOGENERATED — retourne l'URL d'accès
```

Pour un plan sans `accessUrl` (ou `accessUrl: ""`), le fichier `links.env` généré est vide et le verbe `url.sh` retourne un code de sortie 1.

### 2.4 Format du `links.env` généré

Le format reste compatible avec la convention v0 :

```env
# AUTOGENERATED, DO NOT EDIT THIS FILE DIRECTLY.
Wetty SSH Web Client=http://localhost:${WETTY_PORT:-3000}
```

- Si `accessUrl` est une URL simple (sans `=`), le label est le `title` du plan.
- Si `accessUrl` contient déjà des paires `label=url`, elles sont reprises telles quelles.

### 2.5 Compatibilité ascendante

Les fichiers `links.env` manuels existants (non générés par k2) continuent de fonctionner. La logique de fallback dans `layer_get_links()` est :

1. Si `links.env` existe (généré ou manuel) → le lire.
2. Sinon → pas de liens.

Les plans existants qui migrent vers `accessUrl` verront leur `links.env` manuel **écrasé** par le fichier autogénéré lors du rendering. Pour migrer, il suffit d'ajouter `accessUrl` dans le `k2.apply.yaml` et de supprimer le `links.env` manuel.

## 3. Verbe `url.sh` — Spécification

### 3.1 Principe

Un nouveau verbe `url.sh` est généré automatiquement par les recettes. Ce verbe retourne l'URL d'accès du plan sur stdout.

### 3.2 Template `verbs/url.sh`

**`recettes/docker-compose/verbs/url.sh`** (template Go) :

```bash
#!/usr/bin/env bash
## AUTOGENERATED, DO NOT EDIT THIS FILE DIRECTLY.
## Verbe url — Retourne l'URL d'accès de {{ .title }}
set -euo pipefail

{{ if .accessUrl -}}
# Résoudre les variables d'environnement dans l'URL
eval echo "{{ .accessUrl }}"
{{- else -}}
echo "Aucune URL d'accès définie pour {{ .name }}" >&2
exit 1
{{- end }}
```

**`recettes/shell-script/verbs/url.sh`** (template Go) :

```bash
#!/usr/bin/env bash
## AUTOGENERATED, DO NOT EDIT THIS FILE DIRECTLY.
## Verbe url — Retourne l'URL d'accès de {{ .title }}
set -euo pipefail

{{ if .accessUrl -}}
eval echo "{{ .accessUrl }}"
{{- else -}}
echo "Aucune URL d'accès définie pour {{ .name }}" >&2
exit 1
{{- end }}
```

### 3.3 Utilisation

```bash
# Via la commande run (v1)
$ anissa run off-grid llm-proxy url
http://localhost:4000

# Directement dans un script d'intégration
$ bash layers/3.proxy/llm-proxy-ollama/verbs/url.sh
http://localhost:4000
```

## 4. Commande `anissa urls` — Spécification

### 4.1 Syntaxe

```bash
anissa urls <stack>
```

| Argument | Obligatoire | Description |
|---|---|---|
| `<stack>` | Oui | Nom de la stack (sans `.yaml`) |

### 4.2 Comportement

La commande affiche un tableau consolidé des URLs d'accès de tous les plans de la stack qui déclarent un `accessUrl` ou un `links.env`.

### 4.3 Algorithme

```
1. Charger .env si présent
2. Parser stacks/<stack>.yaml
3. Exporter les variables env globales de la stack
4. Pour chaque layer :
   a. Exporter les variables env de la layer
   b. Résoudre le chemin du plan
   c. Lire le links.env (généré ou manuel)
   d. Résoudre les variables d'environnement dans les URLs
   e. Collecter les paires label=url
5. Afficher le tableau consolidé (même format que le résumé de links dans `anissa up`)
```

### 4.4 Exemple de sortie

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  anIssA ▶ urls off-grid
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  SERVICE                          URL
  ──────────────────────────────── ──────────────────────────────
  Ollama                           http://localhost:11434
  LLM Proxy API                    http://localhost:4000
  LLM Proxy UI                     http://localhost:4000/ui
  Wetty Terminal                   http://localhost:3000
  Open WebUI                       http://localhost:8080
  Code Server (IDE)                http://localhost:8443

```

### 4.5 Fonction `layer_get_url()`

Ajoutée dans `anissa/lib/layers.sh` :

```bash
# Retourne l'URL d'accès d'un plan (première URL si multiples)
# $1 = chemin absolu du plan
# Sortie : l'URL brute (non résolue) ou vide si pas d'URL
layer_get_url() {
  local plan_dir="$1"
  local links_file="${plan_dir}/links.env"

  if [[ -f "$links_file" ]]; then
    # Lire la première ligne non-commentaire non-vide
    grep -v '^#' "$links_file" | grep -v '^\s*$' | head -1 | sed 's/^[^=]*=//'
  fi
}
```

### 4.6 Aide CLI mise à jour

La commande `anissa help` affiche désormais :

```
  Commandes :
    ...
    urls <stack>                Afficher les URLs d'accès de la stack
    ...

  Exemples :
    anissa urls off-grid              # afficher les URLs
```

## 5. Modifications de `anissa up` et `anissa status`

### 5.1 `anissa up` — Affichage systématique des URLs

La section d'affichage des liens en fin d'opération (§5.4 étape 9 de v0) est améliorée :

- **Avant (v0/v1)** : seuls les plans possédant un `links.env` manuel étaient listés.
- **Après (v2)** : tous les plans de la stack possédant un `accessUrl` (via `links.env` autogénéré) sont listés.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  ✓ Stack off-grid démarrée (4/4 layers)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Accès aux services :
  ──────────────────────────────── ──────────────────────────────
  Ollama                           http://localhost:11434
  LLM Proxy API                    http://localhost:4000
  Wetty Terminal                   http://localhost:3000
  Open WebUI                       http://localhost:8080

```

### 5.2 `anissa status` — URL à côté du statut

Le tableau de statut affiche désormais une colonne URL optionnelle :

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  anIssA ▶ status off-grid
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  LAYER                                    STATUT     URL
  ──────────────────────────────────────── ────────── ──────────────────────────
  2.locals-subscriptions/ollama-embedded   ✓ UP       http://localhost:11434
  3.proxy/llm-proxy                        ✓ UP       http://localhost:4000
  6.workspace/claude-code-in-container     ✓ UP
  10.clients/wetty                         ✓ UP       http://localhost:3000

```

Les plans sans URL d'accès affichent une cellule vide dans la colonne URL.
