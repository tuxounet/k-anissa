# K-anIssA — Spécification v1

> Ajout du mode debug pour afficher les détails d'exécution du CLI.

---

## Changements par rapport à v0

### Résumé

- **Ajout** : Mode debug activable via le flag `--debug` ou la variable d'environnement `ANISSA_DEBUG=1`.
- **Ajout** : Fonction `log_debug()` dans `anissa/lib/logging.sh`.
- **Ajout** : Support du flag `DEBUG=1` dans le `Makefile` racine.
- **Modification** : Aide CLI mise à jour avec la documentation du flag `--debug`.

### Justification

Le CLI v0 masque par défaut la sortie Docker pour rester lisible (cf. §5.2.6 de v0). Cependant, en cas de problème, l'utilisateur n'a aucun moyen de voir les détails d'exécution internes (résolution de chemins, variables exportées, commandes Docker exécutées, contenu des hooks, rendering k2). Le mode debug comble ce manque en fournissant un niveau de verbosité supplémentaire, activable à la demande.

### Impact sur v0

Aucun changement de comportement par défaut. Le mode debug est **désactivé** par défaut (`ANISSA_DEBUG=0`). Toutes les fonctionnalités v0 restent identiques.

## 1. Mode debug — Spécification

### 1.1 Activation

Le mode debug peut être activé de deux façons (combinables) :

| Méthode | Exemple | Portée |
|---|---|---|
| Flag CLI `--debug` | `anissa --debug up off-grid` | Invocation courante uniquement |
| Variable d'environnement `ANISSA_DEBUG=1` | `ANISSA_DEBUG=1 anissa up off-grid` | Session/invocation courante |
| Variable dans `.env` | `ANISSA_DEBUG=1` dans `.env` | Toutes les invocations |
| Flag Makefile `DEBUG=1` | `make up DEBUG=1` | Invocation make courante |

**Priorité** : Le flag `--debug` force `ANISSA_DEBUG=1` indépendamment de la variable d'environnement.

**Position du flag** : Le flag `--debug` doit être placé **avant la commande** :

```bash
anissa --debug up off-grid     # ✓ correct
anissa up --debug off-grid     # ✗ non reconnu
```

### 1.2 Fonction `log_debug()`

Ajoutée dans `anissa/lib/logging.sh` :

```bash
# Log de débogage (DIM + CYAN icône, uniquement si ANISSA_DEBUG=1)
log_debug() {
  if [[ "${ANISSA_DEBUG:-0}" == "1" ]]; then
    echo -e "${DIM}${CYAN}🔍${RESET} ${DIM}$*${RESET}"
  fi
}
```

**Comportement** :
- Ne produit aucune sortie si `ANISSA_DEBUG` n'est pas `1`.
- Utilise le style `DIM` pour se distinguer visuellement des logs normaux.
- Préfixée par l'icône 🔍 pour identification rapide.

### 1.3 Informations affichées en mode debug

Le mode debug ajoute des logs aux points suivants de l'exécution :

| Phase | Informations affichées |
|---|---|
| **Démarrage CLI** | Confirmation du mode debug, valeurs de `ANISSA_ROOT`, `ANISSA_DATA`, `ANISSA_NETWORK`, arguments reçus |
| **Chargement .env** | Chemin du fichier `.env` chargé (ou absence) |
| **Parsing de stack** | Chemin du fichier stack YAML, variables globales exportées, layers parsées (path + plan) |
| **Export env layer** | Variables d'environnement exportées pour chaque layer, chargement de `defaults.env` |
| **Résolution de chemin** | Chemin résolu pour chaque plan (`layer_resolve_path`) |
| **Rendering k2** | Chemin du binaire k2 utilisé, commande exécutée, output du rendering |
| **Réseau Docker** | Vérification/création du réseau |
| **Docker Compose** | Commande `docker compose` complète exécutée pour chaque opération |
| **Hooks** | Contenu du hook extrait du `k2.apply.yaml` avant exécution |
| **Start/Stop** | Commande Docker Compose exécutée dans chaque plan |

### 1.5 Makefile — Support du flag DEBUG

Le `Makefile` racine supporte le flag `DEBUG=1` :

```makefile
DEBUG ?=
_DEBUG_FLAG := $(if $(filter 1,$(DEBUG)),--debug,)

up:
	@./anissa/bin/anissa $(_DEBUG_FLAG) up $(STACK)
```

**Utilisation** :

```bash
make up DEBUG=1                # Mode debug
make up DEBUG=1 STACK=lab      # Mode debug sur une stack spécifique
make up                        # Mode normal (pas de debug)
```

### 1.6 Variable réservée

| Variable | Défaut | Description |
|---|---|---|
| `ANISSA_DEBUG` | `0` | Active le mode debug si définie à `1`. Affiche les détails d'exécution internes du CLI. |

Cette variable s'ajoute au tableau §3.4 de v0 (Variables réservées `ANISSA_*`).

### 1.7 Aide CLI mise à jour

La commande `anissa help` affiche désormais :

```
  Options :
    --debug                   Activer le mode debug (détails d'exécution)

  Variables d'environnement :
    ANISSA_DEBUG=1            Activer le mode debug via variable
```
